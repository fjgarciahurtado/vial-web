# vial-web

Web port of [vial-gui](https://github.com/vial-kb/vial-gui) (Python/PyQt5, checked out at `../vial-gui`).
Goal: a modern configurator that non-expert users can understand without reading docs.

Stack: Vite + React 19 + TypeScript, Tailwind CSS v4, shadcn/ui, Zustand, WebHID.
Desktop wrapper (Tauri 2 + Rust `hidapi`) is planned, not started.

## Commands

- Install: `npm ci`
- Dev server: `npm run dev`
- Unit tests: `npm test` (Vitest, `src/**/*.test.ts`)
- End-to-end tests: `npm run test:e2e` (Playwright, uses the demo keyboard)
- Lint: `npm run lint` (oxlint; warnings in `src/components/ui` are generated shadcn code)
- Build: `npm run build`

## Layout

- `src/core/` — protocol and data, no React. Must stay UI-free so the Tauri build can reuse it.
  - `transport.ts` — `HidTransport` interface: one 32-byte report out, one back.
  - `webhid-transport.ts` — browser implementation, plus reconnect and unplug events.
  - `vial-client.ts` — VIA/Vial commands, ported from `vial-gui/src/main/python/protocol/`.
  - `keyboard.ts` — reads everything about a connected keyboard (`loadKeyboard`).
  - `keymap-editor.ts` — writes keys and knobs, with undo/redo.
  - `layout.ts` — KLE layout, layout options, key placement.
  - `keycodes/` — keycode catalogue. `data/*.json` and `__fixtures__/` are generated by
    `python -I scripts/extract_keycodes.py ../vial-gui src/core/keycodes/data`; don't edit them by hand.
  - `backup.ts` — `.vil` files, compatible with vial-gui. `unlock.ts` — unlock flow.
  - `keycodes/builders.ts` — combined keys (shortcuts, tap-hold). `lighting.ts`, `matrix.ts` (key tester),
    `macros.ts` (byte format tested against vial-gui's own fixtures).
  - `fake-keyboard.ts` — firmware simulator for tests. `demo.ts` uses it for "Try a demo keyboard".
- `src/store.ts` — app state. `src/components/` — UI.

## Porting rules

- When porting a protocol feature, read the matching vial-gui Python first and cite it in a comment.
- Test protocol code against `FakeTransport` with byte-level expectations before wiring UI.
- Copy is for non-experts: plain words ("Right Shift", not `KC_RSFT`); errors say what happened and how to fix it.
- Anything that can brick a keyboard (firmware flashing, EEPROM reset) needs an explicit confirmation step.
- Colours: use the palette tokens in `src/index.css` (`ink`, `panel`, `field`, `line`...), never `bg-white`,
  so dark mode keeps working. Keycaps use `cap`/`legend`, which stay the same in dark mode.
- Python one-off edits must pass `encoding="utf-8"`; the Windows default (cp1252) corrupts files.
- Don't write code containing backslash escapes (such as a newline escape in a string or regex)
  through Bash heredocs here: they arrive as real newlines. Use the Write and Edit tools instead.
